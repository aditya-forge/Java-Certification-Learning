# How I'm approaching this course

A few habits I want to follow, partly from the course intro and partly from my own experience getting stuck before.

**Type the code, don't copy it.** Typing it out makes me notice details like semicolons, braces and capital letters that I skip over when reading.

**Work a small example by hand first.** Before writing a method, do the problem on paper with a tiny input and pay attention to the steps I actually take. Those steps usually become the code.

**Run often.** Write a few lines, compile, test. Finding an error in five new lines is much easier than in fifty.

**Read the error message properly.** The compiler tells you the file, the line number and what it expected. Most of the time the fix is on that line or the one just before it.

**Test with more than one input.** A method that works for one input can still be wrong. Try an empty case, a single item, and something bigger.

**Keep notes short.** These notes are for revision later, so I only write down what I'd actually need to look up again.
